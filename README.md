名称未定、仮称”MyTock”
mytock-project.git

概要

未来の指定された日時に生成される公開鍵で文書を暗号化する。その日時が訪れるまでユーザ側は文書を確認できない。

キーワード：タイムロック暗号化、管理

主な機能
- 文書のタイムロック暗号化
- 文書の復号
- 復号結果の確認
- 復号結果をファイルに書き込み

管理機能
- タイムロック暗号化した文書をgoogle driveにバックアップ
- タイムロック暗号化した文書を追加・削除
- いつ復号できるのかファイルサイズや作成日といった情報の表示

絶対条件
- 数年後にも復号できるよう努めること
- 暗号化する文書は最悪ロストする可能性があることを把握しておくこと

## 🚀 "MyTock" 開発ロードマップ

### Phase 1: コアロジックの構築（CLI基礎）
- **実装機能**:
    
    - `mytock encrypt <file> --duration 1h`: 指定した時間で封印。
        
    - `mytock decrypt <file>`: 復号（時間が早ければエラーを出す）。
        

### Phase 2: ローカル管理機能の実装

「何を封印したか」を管理するデータベース（台帳）を作ります。

- **メタデータの保存**: 封印したファイル名、解禁日時、Drandのラウンド番号などを、ローカルのJSONまたはSQLiteに記録します。
    
- **ステータス表示**: 現在封印中のファイルの一覧と、解禁までのカウントダウンを表示する `list` コマンドを実装します。
    
- **こだわりポイント**: gomaさんの「面倒くさい」を解決するため、解禁済みのファイルを一括復号する機能などを持たせます。
    

### Phase 3: TUIによるダッシュボード作成

ここが開発のハイライトです。

- **Bubble Teaの導入**: TUIフレームワーク **Bubble Tea** を使い、視覚的な管理画面を作ります。
    
- **UIデザイン**:
    
    - 上下キーで封印ファイルを選択。
        
    - 右側に詳細情報（解禁まであと○日、ファイルサイズなど）を表示。
        
    - 進行状況をプログレスバーで表示。
        
- **生産者の手触り**: ターミナルをフルに使った、gomaさん専用の「JARVIS」のような操作感を目指します。
    

### Phase 4: クラウド連携とバックアップ

「万が一」に備えるフェーズです。

- **Google Drive APIの実装**: 封印時に自動的に暗号化ファイル（`.tlock`）と管理台帳をGoogle Driveへアップロードする機能を付けます。
    
- **同期機能**: 別のPC（ThinkBookなど）でも同じ管理状態を再現できるようにします。
    

### Phase 5: 「数年後」のための永続化処理

絶対条件である「数年後の復号」を確実にします。

- **リカバリーキット生成**:
    
    - 復号に必要な `chain-info`（公開鍵やハッシュ）をテキスト、あるいはQRコード画像として書き出す機能を実装します。
        
- **ソースコードの同梱**: 実行バイナリだけでなく、その時のGoのソースコード一式をアーカイブして保存する「セルフ・アーカイブ機能」を検討します。
